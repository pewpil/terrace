# AGENTS.md

Guidance for AI agents working in this repository. Keep it concise; prune
stale notes as the project evolves and date entries when useful.

## Working style

- **No git usage by the agent.** Do not run git
  commands at all - not even read-only ones (log/show/diff/status) and above
  all not commits - unless the user explicitly asks for it. Version control
  belongs to the user; let them review and commit changes.
- **Discourage big stretch tasks / one-shotting.** Build step by step, verify
  each step (typecheck/lint/build plus a curl smoke test for web pages), and
  confirm before moving on.
- Exception: when the user explicitly says "implement all of them", do all
  approved steps while still verifying after each.
- 2026-11: terrace pivoted from a TUI prototype to the web. The TUI prototype
  (menu + working typing session) is preserved in git history at `f2e2ecc`
  and was deleted from the working tree in `b555924`.

## Nuxt 5 bump (when available)

- Status 2026-11-05: Nuxt 5 is not on npm (`nuxt@latest` is 4.6.4).
  `nuxt.config.ts` already sets `future.compatibilityVersion: 5`; verified with
  prepare/typecheck/lint/build and a production smoke test. Node >=26 already
  meets Nuxt 5's floor. Official guide:
  <https://nuxt.com/docs/5.x/getting-started/upgrade>.
- Check `npm view nuxt dist-tags` first. `npx nuxt upgrade` follows `latest`,
  which may still be 4.x; install the 5.x version explicitly. Match Nuxt's own
  ranges for `vue`, `vue-router` and `@nuxt/eslint`; do not bump blindly.
- The compatibility flag already turns on the Nuxt 5 defaults (case-sensitive
  and typed routes, normalized page names, serializable `definePageMeta`,
  client payload extraction, `clearNuxtState` reset, non-async `callHook`,
  `navigateTo` early return, server-only head composables not auto-imported,
  PostCSS defaults off, Options API compiled out,
  `noUncheckedSideEffectImports`). Remove `future.compatibilityVersion` once
  the 5.x guide says it is redundant.
- Nitro v3: Nuxt 5 runs on Nitro v3; the compatibility flag does not bring it.
  There is no `server/` here yet. When one is added, import handlers/helpers
  from `nuxt/server` (works on 4.6.4 too) instead of relying on h3/nitropack
  auto-imports. Module/Nitro code uses `nitro/*`, not `nitropack`.
- Vite 8/Rolldown: the current build reports Vite 8.3.5. Any future Vite config
  should use `rolldownOptions`/`oxc`, not `rollupOptions`/`esbuild`.
- Verify after the bump: `npx nuxt prepare`, `npm run typecheck`,
  `npm run lint`, `npm run build`, then
  `PORT=4000 node .output/server/index.mjs` and curl `/` (200) plus `/INDEX`
  (404, case-sensitive). Update the Stack pins above and prune this section.

## Design reference - typing session UX (proven in the TUI, ready to port)

- Char states: correct `#c0caf5`, pending `#565f89`, on a mismatch the
  TARGET letter stays visible in error `#f7768e` (terrace preference,
  overriding the TUI-era monkeytype-style "show the typed char"), extras
  show the typed char; caret fg `#7aa2f7` + bg `#283457`.
- Perfect word = no errors AND no backspaces within the word's span,
  including its trailing space; that bumps the streak, anything else resets
  it. The streak counter is wanted in the session UI.
- Stats: wpm = correctChars/5/minutes (needs at least 1s of data), acc =
  (attempts - errors)/attempts over printable keystrokes, time m:ss frozen
  on completion, progress = typed/length; refresh live about every 500ms.
- 3-line sliding passage window, roughly 60-char wrap, current line centered.
- Tab restarts the session; Esc returns to the menu (never bind `q` for quit
  inside a typing screen - it is a typing letter).
- ctrl+backspace deletes a whole space-separated word: clears the active
  word in one go; at a word start it deletes the previous word entirely and
  moves the caret back. Cleared words keep a broken span (never perfect
  again), so the streak does not survive a ctrl-deletion retype.

## Difficulty ladder (terrace-owned, landed 2026-11-06)

- Axis order: beginner, elementary, intermediate, advanced, expert,
  master, general. Full spec (bands, data source, sampling) lives in the
  "Terrace extension" section at the end of
  `investigation/rebuild-report.md`.
- Tiers are disjoint rank bands of the 50k ranked english table
  (1k / 2k / 3k / 6k / 13k / 25k), drawn uniformly inside a band;
  `general` is the whole table weighted by real occurrence counts
  (~93% of draws land in the top-3k head).
- Difficulty is a six-step slider between the topbar and the test (the
  ladder tiers only: beginner..master) with a filled accent track, thumb,
  tick dots and a live name label. `general` is a separate toggle, not a
  slider step: enabling it disables the slider, and toggling it off
  restores the last ladder tier. Selecting any level/mode starts a fresh
  test (seed rerolls). Default is beginner; SSR determinism is unaffected
  (switches only happen after mount).

## Punctuation, numbers & capitalization (terrace-owned, landed 2026-11-06)

- Three independent toggles under the difficulty slider: `punctuation`,
  `numbers` and `capitalization`; any combination works. All default off.
  Each toggle shows an icon (`!?` punctuation, `#` numbers, `Aa`
  capitalization) next to its label. Toggling starts a fresh test (seed
  rerolls), same as a difficulty switch.
- The reference bakes punctuation/numbers into language lists; terrace
  applies them to clean vocabulary words in `app/utils/word-mods.ts`
  (`modifyWord(word, random, { punctuation, numbers, capitalization })`).
  Capitalization is a terrace addition (no reference toggle).
- Punctuation: ~40% of words get one decoration - a matched wrapper
  (`"word"`, `'word'`, `(word)`, `[word]`, `{word}`) or a trailing mark
  (`,` `.` `;` `:` `?` `!`).
- Numbers: ~20% of slots become a 1-4 digit number; with punctuation also
  on they may be `$42`, `87%`, `1,234` or `4.05`.
- Capitalization: ~20% of word slots uppercase their first letter; applied
  before punctuation so it lands inside wrappers (`"Word"`, `Word,`).
  Numbers are unaffected. It is a shift-key drill, not a grammar model.
- Same seeded PRNG as the engine: repeats replay the same words and marks;
  all off consumes no extra draws, so the default stream is unchanged.
- The key handler swallows all printable keys (not just space) so browser
  find-as-you-type does not steal punctuation typing. A lowercase char
  against a capital target is a mismatch. Full spec is in the
  "Terrace extension: punctuation, numbers and capitalization" section of
  `investigation/rebuild-report.md`.

## Design reference - game logic (from older prototypes, not yet ported)

- Markov: order-2 word chain (`buildChain` / `generateText`, with a dead-end
  restart fallback), corpus normalized to lowercase; mulberry32 seeded PRNG.
- Focus mode: gated on >= 50 keystroke observations; weak-bigram practice
  biases the vocabulary toward whole words CONTAINING the pair, never inject
  raw 2-character pairs into word-level output.
- Analytics: perSecondWpm/consistencyScore; sessionDeltas (inter-char latency
  breaks adjacency on backspace); rankWeakRows score = 2*errorRate + capped
  slowness ratio so errors dominate.
- Storage: the TUI-era plan was SQLite via `node:sqlite`; the web equivalent
  is undetermined (probably server-side SQLite in Nitro routes).
